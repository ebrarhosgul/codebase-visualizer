## Summary
This change improves path alias resolution by supporting arrays of fallback paths and nested `tsconfig.json` extraction. The code quality is solid and tests thoroughly cover the new logic. A few minor inconsistencies remain around `jsconfig.json` precedence and fallback behavior, but overall it is a safe and correct improvement.

## Minor
### 🟡 Root jsconfig.json fails to override nested configs, `src/lib/parser/tar-extractor.ts:157`
**Problem**: The condition `(!tsconfigContent || strippedPath === "tsconfig.json")` prevents a root `jsconfig.json` from overriding a previously found nested `tsconfig.json`.
**Why it matters**: A repository with a root `jsconfig.json` and a nested `tsconfig.json` will resolve aliases using the nested file, violating the expected root precedence.
**Suggested fix**: Update the condition to explicitly allow root `jsconfig.json` to override, e.g., `(!tsconfigContent || strippedPath === "tsconfig.json" || strippedPath === "jsconfig.json")`.

### 🟡 Inconsistent fallback for nested configs, `src/lib/parser/ast-parser.ts:534`
**Problem**: The `files.find` fallback explicitly checks `f.path === "tsconfig.json" || f.path === "jsconfig.json"`, which only matches root configurations.
**Why it matters**: If `tsconfigContent` is not provided (e.g. from tests or direct calls), the parser will fail to find nested configurations, unlike the extraction phase which now supports them.
**Suggested fix**: Use `.endsWith("tsconfig.json")` and `.endsWith("jsconfig.json")` to match the logic in `tar-extractor.ts`, and ideally prioritize root configs if multiple are found.

## Nits
- ⚪ `src/lib/parser/ast-parser.ts:534`, `find` will return whichever root config comes first in the array, meaning `jsconfig.json` could arbitrarily take precedence over `tsconfig.json` depending on array order.
