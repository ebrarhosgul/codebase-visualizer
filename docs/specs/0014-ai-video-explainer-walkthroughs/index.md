# 0014. AI video explainer walkthroughs and canvas state sync

**Date**: 2026-11-01
**Status**: Accepted
**Code area**: `src/lib/ai/`, `src/app/api/ai/`, `src/hooks/`, `src/components/trace/`, `src/components/canvas/`, `src/stores/`

## Summary

Reading a long architectural trace is helpful, but watching a short guided video that lights up the dependency graph as it speaks makes complex systems click much faster. You can save a personal Scrimba Explain API key (`scr_live_...`) in an encrypted browser cookie (a small piece of server sealed data that scripts cannot read), generate a 15 to 45 second multi scene walkthrough from any completed answer or with a trace panel toggle, and watch the canvas highlight and center on each file or folder in sync with the video timeline. When no key is saved on the default `facebook/react` sample repository, a pre baked demo walkthrough plays at zero server cost, and when quota limits or missing keys occur on custom repositories, an actionable notice card guides you to add a key or retry.

## Requirements

**User stories**:
- As an engineer exploring a repository, I want to generate a short video walkthrough from an architectural answer or trace panel toggle so that I can watch a guided explanation of how modules connect.
- As a visual learner, I want the graph canvas to highlight and smoothly pan to the active files and dependency edges as the video plays or when I scrub the timeline so that I can follow the code structure visually.
- As a security conscious developer, I want my personal Scrimba Explain API key (`scr_live_...`) stored in an encrypted HTTP only cookie separate from my chat provider key so that my credentials stay safe from browser scripts and never overwrite my text model key.
- As a visitor with no video API key, I want a pre baked interactive walkthrough on the sample repository and a clear quota or key notice card on custom repositories so that I can try synchronized playback immediately and recover cleanly when rate limits hit.

**Acceptance criteria** (the contract, each criterion is IDed and independently checkable):
- **AC-1**: `KeySettingsDialog` and `/api/ai/keys` support the `"scrimba"` video provider alongside `"gemini"`, `"openai"`, and `"claude"`. `KeySettingsDialogProps` accepts `initialProvider?: AiProviderId | "scrimba"`, grouping providers into "Chat Providers" (`gemini`, `openai`, `claude`) and "Video Provider" (`scrimba`). Submitting a Scrimba key validates the `scr_live_` prefix (minimum 16 characters, maximum 1024 characters) and stores it in a dedicated AES 256 GCM (authenticated encryption) HTTP only cookie named `cv_ai_key_scrimba` with `SameSite=Strict`, `path="/"`, and `secure` enabled in production, leaving any existing `cv_ai_key` chat cookie intact. `GET /api/ai/keys` returns `{ hasKey, provider, hasVideoKey, videoProvider }` with `Cache-Control: no-store, max-age=0`, and `DELETE /api/ai/keys?scope=video` clears `cv_ai_key_scrimba` without deleting the chat cookie.
- **AC-2**: Inside `TracePanel`, you can trigger a video walkthrough in two ways: by clicking a "Generate Video Walkthrough" button on any completed assistant message card, or by enabling a sticky "Video Walkthrough" toggle in the trace input bar (which stays enabled across turns until you toggle it off, and automatically starts video generation as soon as each assistant text and path trace finishes). Only one video walkthrough job per `AiQueryMessage.id` is active at a time (`1:1`).
- **AC-3**: When no `cv_ai_key_scrimba` cookie is set and `isVideoDemoRepository(repository.fullName)` is true (`repository.fullName.toLowerCase() === "facebook/react"`), triggering a walkthrough runs a local pre baked demo walkthrough (`providerId: "demo"`) in the browser with zero requests to `/api/ai/video`, resolving immediately to `status: "complete"` with an in memory base64 WebM/MP4 `Blob` URL (`DEMO_WALKTHROUGH_VIDEO_BASE64` in `src/lib/ai/video/demo-walkthrough.ts`) and 3 to 6 deterministic `VideoTimelineCue` chapters derived from the message `PathTrace` or top cited files in `CodebaseGraph`. When no video key is set on any other repository (such as `vercel/next.js`), clicking generate does not call `/api/ai/video` and renders an `AiFallbackNotice` card (`code: "auth_error"`, `suggestedAction: "open_keys"`) with a one click button that opens `KeySettingsDialog` with `initialProvider="scrimba"`.
- **AC-4**: With a valid `cv_ai_key_scrimba` cookie, triggering a walkthrough sends `POST /api/ai/video` with `{ repositoryFullName, messageId, prompt, answerText, targetDurationSeconds, chapters }`. The server route decrypts `cv_ai_key_scrimba`, calls Scrimba Explain `POST /api/v1/explainers` using `Authorization: Bearer <key>` (never placing the key in URLs or logs), and returns HTTP 202 with `{ jobId, status: "queued" | "polling", durationSeconds, upstreamScenes }`, where `durationSeconds` is bounded to 15 to 45 seconds. On the client, `useVideoWalkthrough` runs `buildValidatedVideoCues` against `useGraphStore.getState().graph` to attach 3 to 6 validated initial `VideoTimelineCue` chapters to the job.
- **AC-5**: While a job is in `"queued"` or `"polling"` state, `useVideoWalkthrough` polls `GET /api/ai/video/[jobId]` with backoff formula `delayMs = Math.min(10000, Math.round(4000 * Math.pow(1.5, pollAttempt)))` (`4000ms`, `6000ms`, `9000ms`, `10000ms` cap) up to a 120 second total timeout. While upstream is still processing, `GET /api/ai/video/[jobId]` returns HTTP 200 with `{ jobId, status: "polling", videoUri: null, durationSeconds }`, and the trace panel renders an accessible progress state showing elapsed seconds and chapter preview titles. When Scrimba `GET /api/v1/explainers/[jobId]` completes, the route returns HTTP 200 with `{ jobId, status: "complete", videoUri, durationSeconds, upstreamScenes }`, where `videoUri` passes `isAllowedVideoUri` (HTTPS Scrimba CDN origin or `blob:` / `data:video/` for local demo) and the client merges `upstreamScenes` with validated `CodebaseGraph` node and edge IDs via `buildValidatedVideoCues`.
- **AC-6**: Every `VideoTimelineCue` array produced by `buildValidatedVideoCues` on the client satisfies three invariants against the active `CodebaseGraph`: (1) contiguous non overlapping time intervals `[startTimeSeconds, endTimeSeconds]` covering `[0, durationSeconds]` ordered by `index` (`0..N`), (2) every ID in `nodeIds`, `edgeIds`, and `focalNodeId` exists in `graph.files`, `graph.symbols`, or `graph.edges` (unknown IDs are pruned, and if `upstreamScenes` is empty or lacks valid timestamps, total `durationSeconds` is partitioned into equal proportional slices across the message `PathTrace` hops or cited `fileId` list), and (3) `focalNodeId` defaults to the first valid ID in `nodeIds` or `null` if `nodeIds` is empty.
- **AC-7**: When `status === "complete"`, `VideoWalkthroughPlayer` renders inline inside the corresponding `AiQueryMessage` card in `TracePanel` using a native HTML5 `<video>` element initialized in a paused state at `0:00` (avoiding browser autoplay policy rejections) with a custom control bar styled to `design.md`: play and pause button, current time and duration readout, interactive chapter timeline scrubber with clickable cue markers, active chapter title and narration caption, and an "Auto pan canvas" toggle (`isVideoAutoPanEnabled`, default `true`).
- **AC-8**: During playback and timeline scrubbing, native `<video>` `timeupdate` and `seeked` events run a pure cue lookup (`findActiveCueIndex(cues, currentTimeSeconds)`) and dispatch a Zustand store update (`setVideoCueHighlight`) **only** when `activeCueIndex` changes (never on every `timeupdate` tick when the cue index is unchanged). Setting an active cue sets `highlightSource: "video"`, populates `highlightedNodeIds` with `cue.nodeIds`, `highlightedEdgeIds` with `cue.edgeIds`, and `videoFocalNodeId` with `cue.focalNodeId`, dims non highlighted nodes on `ArchitectureCanvas`, and animates `highlightedEdgeIds` in cyan (`#38bdf8`) when non empty. When `isVideoAutoPanEnabled` is `true`, transitioning to a new cue with a non null `videoFocalNodeId` smoothly centers the React Flow camera via `setCenter(centerX, centerY, { zoom: 1.2, duration: 800 })`.
- **AC-9**: If you manually drag or zoom the React Flow canvas (`onMoveStart` with a non null user DOM event) while `highlightSource === "video"` and `isVideoAutoPanEnabled` is `true`, `isVideoAutoPanEnabled` automatically flips to `false` so the camera stops fighting manual exploration, and `VideoWalkthroughPlayer` displays a "Resume sync" button that restores `isVideoAutoPanEnabled: true` and immediately re centers on the current cue's `videoFocalNodeId`.
- **AC-10**: When a cue's `nodeIds` or `videoFocalNodeId` belong to a file inside a collapsed directory (`n.type === "collapsedFolder"`) or a folder group (`n.type === "folderGroup"`), `ArchitectureCanvas` highlights that visible container node (`hasActiveChild: true`) and uses that container node's coordinates for `setCenter` when centering on a collapsed `videoFocalNodeId`. When one or more cue `nodeIds` are hidden by active layer filters or search queries (not in `visibleFileIds`), the player footer shows `"N cue nodes hidden by current filters"` with a `"Show all"` button that calls `clearLayerFilters()`, `expandAllFolders()`, and `setSearchQuery("")` without modifying `hideExternal`.
- **AC-11**: Upstream and route failures map through `classifyError` in `src/lib/ai/error-classifier.ts` (extended so `ClassifyErrorInput.provider` accepts `AiProviderId | "scrimba" | "demo"`) into structured `AiFallbackNotice` payloads: HTTP 401 or 403 maps to `code: "auth_error"` with `suggestedAction: "open_keys"`; HTTP 429 on video routes maps to `code: "rate_limit"` with `suggestedAction: "retry"`, `retryAfterSeconds` (parsed from `Retry-After` or body, defaulting to 60 seconds), and a live countdown timer; a 120 second polling timeout maps to `code: "network_timeout"` with `suggestedAction: "retry"`. `sanitizeErrorMessage` scrubs `scr_live_[0-9A-Za-z_-]{12,}` tokens from all logs and responses. If `<video>` emits a media error (such as an expired signed URL after reload), the player displays a "Refresh video" action that re polls `GET /api/ai/video/[jobId]` or offers "Regenerate", while keeping manual chapter cue clicking active so you can still step through the canvas highlights without video audio.
- **AC-12**: `VideoWalkthroughJob` metadata is persisted per repository inside the client session thread in `sessionStorage`. Switching repositories (`repositoryFullName` change), clicking "Clear chat", clicking "Clear Glow" (which renders whenever `Boolean(activeTrace) || highlightSource === "answer" || highlightSource === "video"`), or selecting a node on the canvas (`selectNode` / `navigateToTarget`) aborts any in flight `AbortController` for video initiation or polling, pauses video playback, and resets `highlightSource: null`, `videoFocalNodeId: null`, `highlightedNodeIds: []`, and `highlightedEdgeIds: []`. `checkWindow` in `src/lib/ai/rate-limiter.ts` accepts a configurable `windowMs` parameter so `POST /api/ai/video` enforces 10 job creations per 60 minutes (`60 * 60 * 1000`) per IP and `GET /api/ai/video/[jobId]` enforces 120 poll requests per 10 minutes (`10 * 60 * 1000`) per IP with a strict alphanumeric Zod schema on `jobId` (`/^[a-zA-Z0-9_-]{4,128}$/`).

## Decision

**Chosen option**: Option 2: Dedicated `/api/ai/video` REST + polling pipeline with client side `CodebaseGraph` cue validation, a native HTML5 `<video>` cue sync engine, and a `"video"` highlight source on `useGraphStore`.

We will extend the encrypted cookie boundary to store a dedicated `cv_ai_key_scrimba` credential, introduce two stateless Next.js route handlers (`POST /api/ai/video` and `GET /api/ai/video/[jobId]`), validate and normalize timeline cues on the client against the in memory `CodebaseGraph` (`src/lib/ai/video/cue-mapper.ts`), and render a zero dependency HTML5 `<video>` walkthrough player inline inside `AiQueryMessage` cards in `TracePanel` that updates `useGraphStore` only on discrete cue boundary transitions.

The RECOMMEND calls made here (each with the runner up):

- **Separate `cv_ai_key_scrimba` cookie instead of overwriting `cv_ai_key`**: storing the Scrimba key in its own `cv_ai_key_scrimba` cookie lets you keep a Gemini, OpenAI, or Claude key active for text queries while using Scrimba for video walkthroughs. Runner up: reusing the single `cv_ai_key` cookie for all providers, rejected because saving a video key would overwrite the chat model key and break the next text question.
- **Cookie `SameSite=Strict` on `cv_ai_key_scrimba`**: video generation and key management are strictly same origin JSON/fetch requests, never top level cross site navigations, so `SameSite=Strict` provides maximum CSRF protection alongside `isSameOriginRequest(req)`. Runner up: `SameSite=Lax`, rejected because video routes never need cross site top level navigation cookie delivery.
- **Client side cue validation in `useVideoWalkthrough` rather than sending `CodebaseGraph` to `/api/ai/video`**: `CodebaseGraph` already lives in `useGraphStore` in the browser; running `buildValidatedVideoCues` on the client avoids uploading megabytes of graph JSON on video requests while guaranteeing every `nodeId` and `edgeId` exists in `graph.files`, `graph.symbols`, and `graph.edges`. Runner up: uploading the full `CodebaseGraph` to `/api/ai/video`, rejected for unnecessary payload size and serialization cost.
- **Keep `useGraphStore` video slice minimal (`highlightSource: "video"`, `videoFocalNodeId`, `isVideoAutoPanEnabled`)**: high frequency media state (`isPlaying`, `currentTimeSeconds`, `activeCueIndex`) and the sticky input bar toggle (`isVideoModeEnabled`) stay local to `VideoWalkthroughPlayer` and `TracePanel`, while `useGraphStore` holds only the canvas relevant fields updated on cue transitions. Runner up: storing `isPlaying` and `currentTimeSeconds` in `useGraphStore`, rejected because media play/pause and time ticks have no consumers on the canvas and would bloat store selectors.
- **Check both `collapsedFolder` and `folderGroup` nodes in `ArchitectureCanvas`**: `src/graph/adapters/react-flow-adapter.ts` emits collapsed folders as `type: "collapsedFolder"` and expanded folders as `type: "folderGroup"`, so `ArchitectureCanvas` checks both node types when lighting up `hasActiveChild` and resolving fallback camera coordinates for a collapsed `videoFocalNodeId`. Runner up: auto expanding collapsed folders during playback, rejected because mutating filter state mid video triggers an expensive Web Worker layout pass.
- **In memory base64 WebM/MP4 `Blob` URL for `facebook/react` demo mode**: `src/lib/ai/video/demo-walkthrough.ts` constructs a `Blob` URL from a compact embedded WebM/MP4 base64 constant so `<video>` plays natively offline with zero network fetches and no `MEDIA_ERR_SRC_NOT_SUPPORTED` errors. Runner up: an SVG data URI or remote MP4 URL, rejected because `<video>` cannot play SVG data URIs and remote URLs break offline parity.
- **Implementation skills**: `modern-web-guidance` (`~/.gemini/config/plugins/modern-web-guidance-plugin/skills/modern-web-guidance/`) · `chrome-devtools` (`~/.gemini/config/plugins/chrome-devtools-plugin/skills/chrome-devtools/`)

**State transitions**:

1. **Walkthrough job lifecycle (`VideoWalkthroughJob.status`)**:
   - `idle` (no job on message) → `queued` (on `POST /api/ai/video` 202 response)
   - `queued` → `polling` (on `GET /api/ai/video/[jobId]` 200 response while upstream `status` is `"queued"` or `"processing"`)
   - `queued | polling` → `complete` (when `GET /api/ai/video/[jobId]` returns `status: "complete"` with valid `videoUri` and client validated `cues`, or immediately in `facebook/react` demo mode)
   - `queued | polling` → `failed` (on upstream `"failed"`, HTTP 401/403/429/5xx, 120s client polling timeout, or user abort; attaches `errorNotice: AiFallbackNotice`)
   - `failed | complete` → `queued` (when you click "Retry" or "Regenerate", replacing the job on that `AiQueryMessage`)
2. **Canvas highlight state (`highlightSource` in `useGraphStore`)**:
   - `null | "trace" | "answer"` → `"video"` on `setVideoCueHighlight({ nodeIds, edgeIds, focalNodeId })` (sets `activeTrace = null`, `activeStepIndex = null`, `highlightedNodeIds = nodeIds`, `highlightedEdgeIds = edgeIds`, `videoFocalNodeId = focalNodeId`, `highlightSource = "video"`)
   - `"video"` → `null` on `clearTrace()`, `setGraph()`, `selectNode()`, `navigateToTarget()`, or repository change (resets `highlightedNodeIds = []`, `highlightedEdgeIds = []`, `videoFocalNodeId = null`, `highlightSource = null`)
   - `"video"` → `"trace"` on `setActiveTrace(trace)` · `"video"` → `"answer"` on `setAnswerHighlight(nodeIds)` (strictly one highlight source active at a time)
3. **Camera auto pan state (`isVideoAutoPanEnabled`)**:
   - `true` (default when playback starts) → `false` when you toggle the player's "Auto pan" switch off OR manually drag/zoom the React Flow canvas (`onMoveStart` with a non null user event while `highlightSource === "video"`)
   - `false` → `true` when you click "Resume sync" or re enable the "Auto pan" toggle (immediately centers the camera on the active cue's `videoFocalNodeId`)

| Rate limit notice countdown | `retryAfterSeconds` | Upstream `Retry-After` HTTP header (in seconds) on 429 responses, or local rate limiter window reset seconds from `checkWindow`, passed into `classifyError({ status: 429, retryAfterSeconds, provider: "scrimba", suggestedAction: "retry" })` |

**Key invariants**:
- `cv_ai_key` (chat key) and `cv_ai_key_scrimba` (video key) are independent cookies with distinct `COOKIE_PURPOSE` strings (`"ai-key"` vs `"video-key"`) so a ciphertext from one cookie can never be replayed into the other.
- `scr_live_` keys never appear in client accessible state, URL query parameters, server logs, or error responses; `sanitizeErrorMessage` redacts `/scr_live_[0-9A-Za-z_-]{12,}/g` to `"[REDACTED_API_KEY]"`.
- Every `VideoTimelineCue` in a job has `0 <= startTimeSeconds < endTimeSeconds <= durationSeconds`, `cue[0].startTimeSeconds === 0`, `cue[last].endTimeSeconds === durationSeconds`, and `cue[i].endTimeSeconds === cue[i + 1].startTimeSeconds`.
- Every ID in `cue.nodeIds`, `cue.edgeIds`, and `cue.focalNodeId` is verified on the client against the loaded `CodebaseGraph` before storing on `AiQueryMessage.videoWalkthrough`; unknown IDs are stripped.
- `useGraphStore` updates for video playback (`setVideoCueHighlight`) fire **at most once per cue transition** (3 to 6 times across an entire 15 to 45 second video during linear playback), never on intermediate `timeupdate` events within the same cue.
- Only one canvas highlight mode (`"trace"`, `"answer"`, or `"video"`) is active at any instant. Starting video playback or clicking a video chapter cue sets `highlightSource = "video"` and clears `activeTrace`; selecting a node on the canvas (`selectNode` / `navigateToTarget`), clicking "Clear Glow", or starting a new trace clears `"video"` and pauses video playback.
- Manual user pan or zoom on `ArchitectureCanvas` during active video sync immediately sets `isVideoAutoPanEnabled = false` without stopping video playback or clearing node highlights.

**Security model**:
- **Credential storage**: `cv_ai_key_scrimba` is sealed with AES 256 GCM via `sealCookiePayload` using `AI_COOKIE_SECRET` and purpose tag `"video-key"`. Cookie flags: `httpOnly: true`, `sameSite: "strict"`, `secure: process.env.NODE_ENV === "production"`, `path: "/"`, `maxAge: CREDENTIAL_COOKIE_TTL_SECONDS`.
- **CSRF & origin enforcement**: `POST /api/ai/keys`, `DELETE /api/ai/keys`, and `POST /api/ai/video` verify `isSameOriginRequest(req)` and reject cross origin requests with HTTP 403.
- **Input & SSRF protection**: `GET /api/ai/video/[jobId]` validates `jobId` against `/^[a-zA-Z0-9_-]{4,128}$/` before constructing `${baseUrl}/api/v1/explainers/${encodeURIComponent(jobId)}`, preventing path traversal or SSRF. Returned `videoUri` values are validated against `isAllowedVideoUri` so an attacker or malformed response cannot inject `javascript:`, `data:text/html`, or arbitrary third party tracking origins into `<video src>`.
- **Rate limiting**: `checkWindow(ip, maxRequests, windowMs)` in `src/lib/ai/rate-limiter.ts` enforces 10 requests per 60 minutes per client IP on `POST /api/ai/video` and 120 requests per 10 minutes per client IP on `GET /api/ai/video/[jobId]`, returning HTTP 429 with `Retry-After` and a structured `AiFallbackNotice` (`suggestedAction: "retry"`).

**Configuration required**:
- `AI_COOKIE_SECRET` (existing): 32+ character secret used by `sealCookiePayload` and `openCookiePayload` to encrypt both `cv_ai_key` and `cv_ai_key_scrimba`.
- `SCRIMBA_API_BASE_URL` (optional): upstream base URL for Scrimba Explain REST calls; defaults to `"https://api.scrimba.com"` when unset.

## Consequences

**Positive**:
- Complex multi hop architectural traces become much easier to follow because audio narration, chapter captions, and canvas node/edge highlights move together automatically.
- Storing `cv_ai_key_scrimba` in a separate encrypted HTTP only cookie with a distinct purpose tag keeps video credentials isolated from chat model credentials so you never lose your Gemini, OpenAI, or Claude session when configuring Scrimba.
- Running `buildValidatedVideoCues` on the client against `useGraphStore.getState().graph` avoids uploading the full graph over the network and guarantees every cue points to valid node and edge IDs.
- Dispatching Zustand updates only when `activeCueIndex` changes (3 to 6 times per video) and keeping high frequency media state local to `VideoWalkthroughPlayer` guarantees zero 60 FPS frame drops on the React Flow canvas during video playback.
- Visitors without a Scrimba key can still experience synchronized video and canvas playback on `facebook/react` offline and at zero server cost.

**Negative / tradeoffs**:
- Asynchronous video generation introduces a 15 to 60 second polling wait on live Scrimba requests before playback begins, requiring clear progress feedback and timeout handling in the trace panel.
- Adding `"video"` as a third `highlightSource` alongside `"trace"` and `"answer"` increases the state transition surface in `useGraphStore` and `ArchitectureCanvas`, governed by the strict one highlight mode at a time rule.
- Signed upstream video URLs stored in `sessionStorage` can expire if a tab sits idle for hours; the player mitigates this with the "Refresh video" re poll action and manual chapter stepping fallback rather than storing multi megabyte video blobs in IndexedDB.

**Neutral**:
- No database schema migration is required because walkthrough job metadata persists in the existing per repository `sessionStorage` thread alongside `AiQueryMessage`.
- Legacy messages in `sessionStorage` without a `videoWalkthrough` field continue to render normally and can initiate a walkthrough on demand.
